## 📚 Описание проекта

**"Знание Севера"** - это комплексная web-система электронного дневника, предназначенная для автоматизации учебного процесса в образовательных учреждениях. Система предоставляет удобные инструменты для администраторов, учителей, учеников и родителей.

Это финальная версия проекта с полноценным PHP backend, структурированным кодом и расширенной функциональностью.

## 🚀 Установка и настройка

### 📋 Предварительные требования

- **PHP 7.4** или выше
- **MySQL 5.7** или выше (рекомендуется 8.0+)
- Web-сервер Apache или Nginx
- Современный браузер (Chrome, Firefox, Safari, Edge)
- Утилита `curl` для работы с API (опционально)

### 📥 Шаг 1: Клонирование репозитория

```bash
git clone https://github.com/razetka2010/znanie-severa-version-final.git
cd znanie-severa-version-final
```

### 🔧 Шаг 2: Настройка базы данных

1. **Создайте базу данных:**

```sql
CREATE DATABASE znanie_severa;
USE znanie_severa;
```

2. **Импортируйте схему базы данных:**

```bash
mysql -u root -p znanie_severa < config/schema.sql
```

`config/schema.sql` создаёт таблицы и системные роли, но не содержит пользователей или демо-данных. Перед импортом создайте базу `znanie_severa`. Не импортируйте SQL-дампы рабочей базы в публичный каталог проекта.

Для уже установленной версии сначала сделайте резервную копию БД, затем примените SQL-файлы из `config/migrations/` по порядку к выбранной базе. Миграции выполняются вручную владельцем/администратором БД; пользователь приложения не выполняет DDL при открытии страниц. Для новой базы импортируйте только `config/schema.sql`.

### ⚙️ Шаг 3: Конфигурация

1. **Настройте подключение к БД.** Если хостинг поддерживает переменные окружения PHP, задайте их в конфигурации сервера вне web-каталога:

```apache
SetEnv DB_HOST "localhost"
SetEnv DB_PORT "3306"
SetEnv DB_NAME "znanie_severa"
SetEnv DB_USER "znanie_severa_app"
SetEnv DB_PASSWORD "replace-with-a-unique-secret"
```

Если хостинг не предоставляет переменные окружения, скопируйте `config/database.local.php.example` в `config/database.local.php` и замените все значения `replace-with-...` реальными реквизитами. Это шаблон, соединение с базой с незаменёнными заглушками не заработает. Файл `config/database.local.php` исключён из Git; каталог `config` закрыт от HTTP-доступа через `.htaccess`. Не загружайте заполненный файл в публичный репозиторий и проверьте, что при прямом открытии его URL сервер отвечает `403 Forbidden`.

Для InfinityFree создайте БД в панели управления → **MySQL Databases**. Возьмите точные Database Name, Username и Hostname из Current Databases, пароль — из клиентской области аккаунта. В качестве hostname используйте выданное значение вида `sqlNNN.infinityfree.com`, не `localhost`. В phpMyAdmin выберите созданную БД → **Import** → загрузите `config/schema.sql`. PHP built-in server и директивы `SetEnv` в `.htaccess` не используйте как способ настройки production на InfinityFree.

Создайте отдельного пользователя MySQL с доступом только к этой базе там, где это поддерживается. `DB_PORT` необязателен (по умолчанию `3306`); остальные параметры обязательны.

2. **Настройте права доступа к папкам:**

```bash
chmod 755 admin/ school_admin/ teacher/ student/
chmod 644 config/*.php includes/*.php
```

3. **Защищенное хранилище отчетов:**

Отчеты автоматически сохраняются в `school_diary_uploads/reports` рядом с каталогом проекта, вне web-корня. Пользователь веб-сервера должен иметь право записи в эту папку; приложение создает ее с правами `0755`. Для проверки типа файлов требуется расширение PHP `fileinfo`. Скачивание выполняется через `reports/download.php` после проверки авторизации и прав доступа.

Для Apache убедитесь, что разрешена обработка `.htaccess`: `config/.htaccess` запрещает HTTP-доступ к каталогу с конфигурацией и SQL-схемой. PHP built-in server предназначен только для локальной разработки, не для публикации приложения в сети. Если сервер использует Nginx, запретите прямой доступ к старым файлам отчетов отдельным правилом:

```nginx
location ^~ /uploads/reports/ {
    deny all;
}
```

Также закройте конфигурационные файлы от HTTP-доступа в конфигурации Nginx:

```nginx
location ^~ /config/ {
    deny all;
}
```

### 🌐 Шаг 4: Запуск сервера

**Вариант 1: Локальный PHP сервер**

```bash
php -S localhost:8000
```

Затем откройте: `http://localhost:8000`

**Вариант 2: Apache/Nginx**

Скопируйте папку проекта в корневую папку сервера (`/var/www/html` для Apache)

### 🔐 Шаг 5: Создание первого администратора

Учетные записи по умолчанию не создаются. Создайте уникальный пароль и получите его хеш с помощью PHP `password_hash()` на сервере. Затем добавьте первого администратора в базу, подставив свои логин, email, ФИО и полученный хеш:

```sql
INSERT INTO users (login, email, password_hash, full_name, role_id, is_active)
SELECT 'your-admin-login', 'admin@example.com', 'paste-generated-password-hash-here',
       'Administrator', id, 1
FROM roles
WHERE name = 'super_admin';
```

Не используйте публичные или повторно используемые пароли. Хеш должен быть получен из выбранного вами пароля через `password_hash($password, PASSWORD_DEFAULT)`.

Если база ранее была создана из старого дампа с демо-пользователями, отключите или удалите эти учетные записи и смените пароли всех реально используемых аккаунтов. Если старые реквизиты БД когда-либо публиковались, замените их и обновите переменные окружения.

## 🔒 Безопасность

### Реализованные меры безопасности

✅ **Аутентификация**
- Использование хеширования паролей (bcrypt/argon2)
- Session-based аутентификация
- Защищённые cookie сессии, смена ID после входа и таймаут бездействия
- Ограничение неуспешных попыток входа: 5 попыток за 15 минут на пару IP/логин
- Выход только POST-запросом с CSRF-токеном; запись сессии удаляется из базы
- Защита от brute-force атак

✅ **Авторизация**
- Role-Based Access Control (RBAC)
- Проверка прав доступа на каждой странице
- Логирование действий администраторов

✅ **Защита данных**
- SQL-injection prevention (prepared statements)
- XSS protection (HTML escaping)
- CSRF protection: все POST-запросы авторизованных страниц проверяются централизованно, формы должны отправлять `csrf_field()`, а изменяющие GET-запросы отклоняются
- Шифрование чувствительных данных

✅ **Протоколирование**
- Логирование входов в систему
- Аудит изменения оценок
- История действий администраторов
